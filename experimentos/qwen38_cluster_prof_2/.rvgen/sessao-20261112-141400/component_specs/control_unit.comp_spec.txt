# Component semantic contract: control_unit

## Public interface
```vhdl
entity control_unit is
    port(
        opcode : in std_logic_vector(6 downto 0);
        funct3 : in std_logic_vector(2 downto 0);
        funct7 : in std_logic_vector(6 downto 0);
        alu_op : out std_logic_vector(3 downto 0);
        alu_src : out std_logic;
        mem_read : out std_logic;
        mem_write : out std_logic;
        mem_width : out std_logic_vector(1 downto 0);
        mem_to_reg : out std_logic;
        reg_write : out std_logic;
        branch : out std_logic;
        jump : out std_logic;
        jump_reg : out std_logic;
        imm_sel : out std_logic_vector(2 downto 0)
    );
end control_unit;
```

## Responsibility
Decode opcode, funct3, and funct7 fields to produce all control signals: ALU operation selector, ALU source mux select, memory read/write enable, memory width, register write enable, memory-to-register select, branch/jump/jump-register enables, and immediate type selector.

## Timing
Purely combinational. All outputs are a function of the current values of `opcode`, `funct3`, and `funct7`. There is no clock, no state, and no propagation delay beyond the physical gate delay. Outputs update whenever any input changes.

## Reset
None. The component has no clock, no reset port, and no internal state.

## Behavior
The component decodes the three instruction fields (`opcode`, `funct3`, `funct7`) and produces the complete set of control signals that configure the datapath for the current instruction. Each output is determined solely by the combination of these three inputs according to the RV32I encoding tables in `## Operations`.

For any `opcode` value not listed in `## Operations`, all outputs shall be driven to their inactive/default values: `alu_op = "0000"`, `alu_src = '0'`, `mem_read = '0'`, `mem_write = '0'`, `mem_width = "00"`, `mem_to_reg = '0'`, `reg_write = '0'`, `branch = '0'`, `jump = '0'`, `jump_reg = '0'`, `imm_sel = "000"`.

## Operations
### Output signal semantics

| Signal | Width | Meaning |
|--------|-------|---------|
| `alu_op` | 4 | Selects the ALU arithmetic/logic operation (see encoding below). |
| `alu_src` | 1 | `'0'`: ALU B-operand is `rs2`. `'1'`: ALU B-operand is the sign-extended immediate. |
| `mem_read` | 1 | `'1'`: assert memory read strobe. |
| `mem_write` | 1 | `'1'`: assert memory write strobe. |
| `mem_width` | 2 | `"00"` = byte, `"01"` = halfword, `"10"` = word. |
| `mem_to_reg` | 1 | `'0'`: ALU result is written to `rd`. `'1'`: memory read data is written to `rd`. |
| `reg_write` | 1 | `'1'`: write-back to register file is enabled. |
| `branch` | 1 | `'1'`: conditional branch instruction; PC update depends on branch condition. |
| `jump` | 1 | `'1'`: unconditional jump (JAL). |
| `jump_reg` | 1 | `'1'`: jump-and-link-register (JALR). |
| `imm_sel` | 3 | Selects immediate format from the immediate generator (see encoding below). |

### `alu_op` encoding

| Value | Mnemonic | ALU result |
|-------|----------|------------|
| `"0000"` | ADD | `A + B` |
| `"0001"` | SUB | `A − B` |
| `"0010"` | SLL | `A << B[4:0]` |
| `"0011"` | SLT | `1` if signed `A < B`, else `0` |
| `"0100"` | SLTU | `1` if unsigned `A < B`, else `0` |
| `"0101"` | XOR | `A ⊕ B` |
| `"0110"` | SRL | `A >> B[4:0]` (logical) |
| `"0111"` | SRA | `A >> B[4:0]` (arithmetic) |
| `"1000"` | OR | `A ∨ B` |
| `"1001"` | AND | `A ∧ B` |
| `"1010"` | PASS_B | `B` (ignores A; used by LUI) |
| `"1011"` | PC_ADD | `PC + B` (ignores A; used by AUIPC) |

### `imm_sel` encoding

| Value | Format | Immediate construction |
|-------|--------|------------------------|
| `"000"` | I | `sext(instr[31:20])` |
| `"001"` | S | `sext(instr[31:25] ‖ instr[11:7])` |
| `"010"` | B | `sext(instr[31] ‖ instr[7] ‖ instr[30:25] ‖ instr[11:8] ‖ '0')` |
| `"011"` | U | `instr[31:12] ‖ "000000000000"` |
| `"100"` | J | `sext(instr[31] ‖ instr[19:12] ‖ instr[20] ‖ instr[30:21] ‖ '0')` |

## Edge cases
1. **Undefined opcode.** Any `opcode` value not in the set `{0x33, 0x13, 0x03, 0x23, 0x63, 0x37, 0x17, 0x6F, 0x67}` shall produce all-default outputs (all zeros). This ensures no register write, no memory access, and no control-flow change for illegal instructions.

2. **Undefined `funct3` within a valid opcode.** For opcodes where `funct3` selects among sub-operations (R-type, I-type ALU, load, store, branch), an undefined `funct3` value (e.g., `funct3 = "001"` for R-type with `funct7 = "0000000"` is SLL, but `funct3 = "001"` with `funct7 = "0100000"` is undefined) shall produce all-default outputs. Specifically:
   - R-type: `funct3 ∈ {000,001,010,011,100,101,110,111}` are all valid only with the `funct7` values listed. Any other `(funct3, funct7)` combination for `opcode = 0x33` yields defaults.
   - I-type ALU: `funct3 ∈ {000,001,010,011,100,101,110,111}` are all valid. For `funct3 = "001"` (SLLI), any `funct7` is accepted (shift amount is in `funct7[4:0]`); for `funct3 = "101"`, only `funct7 = "0000000"` (SRLI) and `funct7 = "0100000"` (SRAI) are valid; other `funct7` values yield defaults.
   - Load: `funct3 ∈ {000,001,010,100,101}` are valid. `funct3 ∈ {011,110,111}` yield defaults.
   - Store: `funct3 ∈ {000,001,010}` are valid. `funct3 ∈ {011,100,101,110,111}` yield defaults.
   - Branch: `funct3 ∈ {000,001,100,101,110,111}` are valid. `funct3 ∈ {010,011}` yield defaults.

3. **JALR `funct3`.** Only `funct3 = "000"` is valid for JALR. Other `funct3` values with `opcode = 0x67` yield defaults.

4. **`funct7` don't-care fields.** For instructions where `funct7` is marked "(don't care)" in the table (ADDI, SLTI, SLTIU, XORI, ORI, ANDI), the decoder shall ignore `funct7` entirely and produce the listed outputs regardless of `funct7` value.

5. **`mem_width` for non-memory instructions.** For all instructions that are not loads or stores, `mem_width` shall be `"00"`. The value is a don't-care from the datapath perspective (since `mem_read` and `mem_write` are both `'0'`), but the decoder must still drive it to `"00"` to avoid floating outputs.

6. **`alu_src` for R-type.** For all R-type instructions, `alu_src` shall be `'0'` regardless of `funct7` or `funct3`.

7. **`alu_src` for branch.** For all branch instructions, `alu_src` shall be `'0'` (both operands come from registers).
