# Component semantic contract: decoder

## Public interface
```vhdl
entity decoder is
    port(
        instr : in std_logic_vector(31 downto 0);
        reg_write : out std_logic;
        mem_write : out std_logic;
        alu_src_a_pc : out std_logic;
        alu_src_b_imm : out std_logic;
        alu_control : out std_logic_vector(3 downto 0);
        branch_enable : out std_logic;
        jump : out std_logic;
        jalr : out std_logic;
        wb_select : out std_logic_vector(1 downto 0);
        m_enable : out std_logic
    );
end decoder;
```

## Responsibility
Decode instruction controls and identify M instructions for M-result writeback.

## Timing

`decoder` is purely combinational. After `instr` changes, every output, including `m_enable`, shall settle without a clock edge. The decoder has no state, handshake, or latency. M-instruction identification must be available in the same cycle as the other controls.

## Reset

None. The decoder has no reset input. Every output is determined solely by `instr`.

## Behavior

Decode opcode from `instr[6:0]`, `funct3` from `instr[14:12]`, and, where required, `funct7` from `instr[31:25]`.

For an unsupported opcode or function encoding, output the complete no-side-effect tuple: `reg_write='0'`, `mem_write='0'`, `alu_src_a_pc='0'`, `alu_src_b_imm='0'`, `alu_control="0000"`, `branch_enable='0'`, `jump='0'`, `jalr='0'`, `wb_select="00"`, and `m_enable='0'`.

For valid instructions, `reg_write` is asserted even if `rd=x0`; the register file suppresses writes to `x0`. `mem_write` is asserted only for valid stores, `branch_enable` only for valid conditional branches, `jump` only for JAL and JALR, and `jalr` only for JALR.

`alu_src_a_pc='1'` selects PC instead of `rs1`; `alu_src_b_imm='1'` selects the applicable immediate instead of `rs2`. Controls are defined even when the selected ALU result does not determine the instruction’s architectural result.

| Valid class | `reg_write` | `mem_write` | `alu_src_a_pc` | `alu_src_b_imm` | `branch_enable` | `jump` | `jalr` | `wb_select` | `m_enable` |
|---|---:|---:|---:|---:|---:|---:|---:|---|---:|
| RV32I OP (`0x33`) | 1 | 0 | 0 | 0 | 0 | 0 | 0 | `"00"` | 0 |
| RV32M OP (`0x33`, `funct7="0000001"`) | 1 | 0 | 0 | 0 | 0 | 0 | 0 | `"00"` | 1 |
| OP-IMM (`0x13`) | 1 | 0 | 0 | 1 | 0 | 0 | 0 | `"00"` | 0 |
| Load (`0x03`) | 1 | 0 | 0 | 1 | 0 | 0 | 0 | `"01"` | 0 |
| Store (`0x23`) | 0 | 1 | 0 | 1 | 0 | 0 | 0 | `"00"` | 0 |
| Conditional branch (`0x63`) | 0 | 0 | 0 | 0 | 1 | 0 | 0 | `"00"` | 0 |
| LUI (`0x37`) | 1 | 0 | 0 | 1 | 0 | 0 | 0 | `"00"` | 0 |
| AUIPC (`0x17`) | 1 | 0 | 1 | 1 | 0 | 0 | 0 | `"00"` | 0 |
| JAL (`0x6F`) | 1 | 0 | 1 | 1 | 0 | 1 | 0 | `"10"` | 0 |
| JALR (`0x67`, `funct3="000"`) | 1 | 0 | 0 | 1 | 0 | 1 | 1 | `"10"` | 0 |

`m_enable='1'` identifies an M instruction and requests M-result writeback; the decoder does not compute that result. For M instructions, `"00"` is the writeback selector value, while `m_enable` identifies the M result rather than an ordinary RV32I ALU result. No non-M instruction asserts `m_enable`.

## Operations

For non-branch RV32I instructions, `alu_control` has these meanings:

| Value | Operation |
|---|---|
| `"0000"` | ADD |
| `"0001"` | SUB |
| `"0010"` | SLL |
| `"0011"` | SLT, signed |
| `"0100"` | SLTU, unsigned |
| `"0101"` | XOR |
| `"0110"` | SRL |
| `"0111"` | SRA |
| `"1000"` | OR |
| `"1001"` | AND |
| `"1010"` | PASS_B |
| `"1011"`–`"1111"` | Not selected for non-branch instructions |

When `branch_enable='1'`, `alu_control` instead selects `"0000"` BEQ, `"0001"` BNE, `"0010"` BLT (signed), `"0011"` BGE (signed), `"0100"` BLTU (unsigned), or `"0101"` BGEU (unsigned). These branch meanings apply only when `branch_enable='1'`.

`wb_select="00"` selects the ordinary ALU result for non-M instructions, `"01"` selects the data-memory read result, and `"10"` selects `PC + 4`. `"11"` is reserved and is never selected by a valid instruction. An asserted `m_enable` identifies M-result writeback as specified in `Behavior`.

JAL’s and JALR’s `alu_control` values do not select jump-target generation. For M instructions, `alu_control="0000"` is a defined, non-selecting value: `m_enable`, together with the instruction’s `funct3`, identifies the M operation for the M-result path. M-result computation—including multiplication, division, and remainder semantics—is not performed by `decoder`.

## Edge cases

- Every one of the eight `funct3` values is valid for OP **only when** `funct7="0000001"` for M decoding. This pattern is not an M instruction under any other opcode. OP encodings with other `funct7` values remain valid only for the exact RV32I combinations listed in `Operations`; all remaining combinations are unsupported.
- ADD and SUB, and SRL and SRA, remain distinguished by their exact `funct7` patterns. M encodings must not be decoded as those RV32I operations.
- SLLI, SRLI, and SRAI require their exact listed upper-bit patterns. Their shift amount in `instr[24:20]` does not select a decoder operation. For non-shift OP-IMM instructions, `instr[31:25]` neither restricts validity nor changes the selected operation.
- Unsupported load, store, branch, and JALR `funct3` values produce the complete no-side-effect tuple. LUI, AUIPC, and JAL have no function-field restrictions.
- Register indices and immediate bits do not alter controls except where instruction bits are explicitly used as opcode or function fields. In particular, `rd=x0` does not deassert `reg_write` for a valid M or RV32I register-writing instruction.
- Division by zero and signed-division overflow remain defined RV32M cases, not unsupported encodings: DIV, DIVU, REM, and REMU retain `m_enable='1'` regardless of operand values. The decoder receives no operands and does not calculate their results.
- Every output, including `m_enable`, has a defined value for every 32-bit `instr`; there are no don’t-care outputs.

## Test strategy

Use a combinational Cocotb test: drive a complete `instr`, allow outputs to settle, and compare **every** output—including `m_enable`—with the expected tuple. Do not supply clock or reset stimulus.

1. Cover every valid class in `Behavior`, including `rd=x0` on both an RV32I and an M register-writing instruction. Check operand selectors, side-effect flags, jump controls, `alu_control`, `wb_select`, and `m_enable`.
2. Exercise all ten listed RV32I OP encodings and all eight M encodings. For each M `funct3`, require `reg_write='1'`, `m_enable='1'`, `wb_select="00"`, `alu_control="0000"`, and the remaining M-class controls. Change `funct7` between `"0000000"`, `"0100000"`, `"0000001"`, and unsupported patterns while holding other fields fixed; verify the exact valid result or complete unsupported tuple.
3. Exercise every OP-IMM row. Check allowed and disallowed SLLI/SRLI/SRAI upper-bit patterns, and vary upper bits for every non-shift OP-IMM operation without changing its controls.
4. Exercise each valid load, store, and branch `funct3`, plus every unsupported `funct3` for those opcodes. Check write versus read selection and each branch-specific ALU selector.
5. Exercise LUI, AUIPC, JAL, and valid JALR. Vary unrestricted function fields for the first three; test all JALR `funct3` values and require the unsupported tuple except for `"000"`. Check JAL and JALR separately for `"10"` writeback, `jump`, and `jalr`.
6. Vary register-index and immediate fields independently where they are not function selectors; require unchanged controls. Check that an M `funct7` pattern under a non-OP opcode cannot assert `m_enable`.
7. Drive representative unknown opcodes and invalid function combinations. Check the entire no-side-effect tuple, explicitly including `m_enable='0'`.
8. Apply consecutive valid RV32I, valid M, and unsupported instructions without a clock, checking outputs after each change to detect stale controls or a stale `m_enable`. DIV/REM instruction encodings must still decode as M instructions: operand-dependent division-by-zero and overflow results belong in M-result-path tests, not decoder tests.
